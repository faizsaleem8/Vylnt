# VYLNT authentication-role evidence

This increment supplies positive native CK-001/CK-002 evidence for a future experimental candidate. It does not qualify either category or enable a new classifier.

## What the producer establishes

The native Tabinator prototype independently checks a signed SQLite session-to-user relationship and actual protected bookmark writes, then uses the same bounded issued authentication-role producer. Its native/readable profiles are one additional development-exposed source. Scope is the native API profile/bookmark operation, not the CDN-dependent frontend or all routes. See `ML_NATIVE_TABINATOR.md`; actual checks are recorded in PLAN.md. It does not create an eligible cohort or qualify a category.

The developer-owned authentication check uses fresh browser contexts for the original cookie state, an anonymous state, removal of one matched cookie and restoration. The original and restored states must authenticate; anonymous and removal states must positively identify an unauthenticated state. Errors and incomplete checks remain unknown. Removing a cookie without an observed effect does not establish a preference role.

`vylnt-project-functional-v2` binds the measurement to the scan digest and adapter identity. Only the original issued measurement can be merged; serialized, edited, stale or differently bound positive measurements are rejected. The authentication-role merger additionally rules out a solely non-sensitive preference role. It does not claim the cookie has no secondary uses, or that every route was checked.

The probe permits bounded GET traffic to the explicit source loopback origin. Response-stage redirect checks prevent following redirects to another service. Extra pages, workers, unsupported requests, ambiguous cookie matching, changed attributes and failed restoration cannot issue positive facts. Cookie values exist only in transient browser state and never enter output or witness hashes. Reviewed offline fallbacks are part of the adapter identity.

## Source inventory and assessment

The bounded syntax inspector recognizes an explicit exported Express initializer assigning a uniquely declared outer variable from an unchanged Express import. Shadowed, conditional and reassigned bindings remain unsupported. This form always retains **partial** inventory coverage. Files outside the registered source root and symbolic-link files cannot supply source inventory.

Assessment policy `vylnt-project-assessment-v3` permits complete positive authentication inputs despite a partial known-Express inventory when authentication and non-sensitive-role exclusion share a complete functional witness. CK-001 also requires the matched cookie to lack Secure. CK-002 requires the matched cookie to lack HttpOnly and have complete JavaScript-necessity checks; an authentication cookie requiring JavaScript remains an architecture review. Existing matching, unknown-context, contradictory-evidence and high-severity safeguards remain.

This exception supports change proposals only. It cannot turn an authentication cookie contextual, even at low severity. V1/V2 policies remain readable with their original decisions. Tensor layout, shared detection rules and the qualified JS-002 release remain unchanged.
