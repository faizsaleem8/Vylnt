## Required implementation before a complete acquisition

1. Establish native non-sensitive cookie purpose and actual JavaScript necessity,
   including misleading names that trigger the original rules.
2. Establish necessary cross-site application flows and independently tested
   CSRF protection, with explicit route coverage.
3. Correlate native resource requests, pre-transfer HTTPS upgrades and successful
   functionality. A completed HTTPS transfer alone is insufficient.
4. Add independently supported framing, effective policy and validated HSTS
   mechanisms in both partitions. Independent protection and compatibility checks
   must support each contextual class.
5. Register each new mechanism and its native evidence requirements before
   acquisition. Distinct paths, policy strings or numerical tensors alone do
   not establish distinct causes.
6. If the pinned native applications lack the required functionality, select and
   register suitable development sources and family assignments before collecting.
   Preserve previous registrations. Consumed qualification families stay excluded.
