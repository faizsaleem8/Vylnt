# VYNLT developer training and release workflow

Ordinary users only scan and download reports. They never annotate, upload a model, train or configure an AI provider. Private reports/review records live under ignored `.local/`, `ml/data/` or another private developer directory. Only bounded numeric weights and a public scope/qualification manifest may be bundled.

1. Run `npm run ml:controlled` after `npm run lab:tls` and `npm run setup:browser`. This starts only ephemeral loopback HTTP/HTTPS servers. Network/header/HTML/resource assertions use Node clients independently of VYNLT detection rules. Scan assertions then verify collection. These generated template variants do not count as independent application families or real-world human reviews.
2. Run `npm run ml:prepare:insights -- --manifest .local/ml-controlled/manifest.json --output .local/ml-controlled/dataset.json` with a private, stable `VYNLT_ML_DATASET_KEY` of at least 32 characters. Keep the key outside Git. The output contains only numeric features, category/severity/coverage, labels, provenance and opaque hashes. No URLs, cookie names, raw code or review prose enter the dataset.
3. Audit before fitting: `npm run ml:insights -- audit --dataset <dataset.json> --output <new-split-audit.json>`. The output is exclusive: do not overwrite a frozen split. Equivalent model inputs join family components so they cannot leak across partitions. Repeated family/context/label rows are removed during preparation and rejected by training validation. Conflicting labels and insufficient-evidence labels require abstention.
4. Train a new candidate directory: `npm run ml:insights -- train --dataset <dataset.json> --output <new-candidate-directory>`. The input hash and split are frozen before fitting. Both training and validation require both classes after conflict/coverage filtering. The LSTM has eight hidden units, at most 74 steps, no external inference service and at most 128 KiB artifact bytes. The logistic comparator sees the same full ordered tensor/length and identical family partitions. Preprocessing fits training only. Validation chooses the LSTM checkpoint, temperature and two decision thresholds. A refused experiment leaves a failure record; do not relabel unknowable cases to make training pass.
5. Evaluate once: `npm run ml:insights -- evaluate --dataset <same-dataset.json> --output <candidate-directory>`. An exclusive consumed marker prevents reusing this candidate's frozen test for threshold searches. Evaluation writes per-category precision, recall, contextual misclassification, abstention coverage, Wilson 95% intervals, class/family counts, rule-only and logistic comparisons, and results before/after safeguards. Failed gates remain published and experimental. Review intervals in light of within-family correlation; they are not universal accuracy guarantees.
6. Perform independent application review. A human-reviewed manifest entry requires `reviewer`, `reviewedAt`, `reviewScope` and `evidenceRecord`. All entries require reportFile/findingIndex, familyId, label and provenance. Controlled entries require oracleVersion/oraclePassed and a ground-truth evidence record. Preparation checks structure; it cannot attest the truth of a review declaration. Audit agreement and related-template grouping independently. Keep private attribution outside bundled sources.
7. Create a private release review JSON: version 1, independentApplicationReview true, datasetHash, evaluationHash (SHA-256 of evaluation file bytes), public scope, approvedCategories and optional name. A category needs every gate in `ML_BUILD_PLAN.md`; controlled-only data cannot approve relevance de-emphasis.
8. Run `npm run ml:release:insights -- --model <model.json> --evaluation <evaluation.json> --review <private-review.json> --output <new-release.json>`. This rejects controlled/synthetic provenance, stale identity and failed gates. Only explicit `--bundle` updates `packages/ml/bundled-evidence.ts`; previous model identities are archived for frozen retrieval. Update PLAN.md, archive versioned policies/templates when changing them and run full unit/Python/browser/PDF checks before release.

Candidate numerical parity is checked against exported PyTorch scores with absolute tolerance 1e-6. Legacy v1 model parsers/fixtures remain for development; synthetic fixtures never determine production relevance. The shipped v2 release is currently null, so users get evidence-summary mode.

The initial controlled fixture intentionally assigns different application intents to equivalent observable metadata. Those conflicts demonstrate an information limit: a recurrent network cannot recover context that was never collected. Additional independently checked scenarios and independently reviewed application data are required before a useful category release.
