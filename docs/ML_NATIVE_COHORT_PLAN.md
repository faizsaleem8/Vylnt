## First additional prototype

Source: [lennysh/tabinator](https://github.com/lennysh/tabinator/tree/51e7cffa382da3d7c710cbfc0d136868c94eb119), repository ID 1087821022, pinned revision `51e7cffa382da3d7c710cbfc0d136868c94eb119`. The inspected native implementation uses Express, express-session, SQLite users and a SQLite session store. Licence: MIT; expected licence Git blob `363777dd09a0ba8fd1f1b9d96cc6b78d4c2f12f0`.

Use a disposable checkout/data directory and a synthetic account. Retain the native authentication/session implementation. Force only the listening interface to loopback with a separately bound runner shim. Consume/discard upstream logs; do not persist request bodies. No Docker, hosted application, real account, external service or production database is used.

Independent controls, specified before collection:

- Register/login through native routes, then positively read the authenticated profile.
- Verify directly in SQLite that the transient browser session maps to that newly created synthetic user. This oracle does not call VYLNT detection rules or use a cookie name as purpose evidence.
- Require native original/anonymous/target-cookie-removed/restored authentication controls.
- Create one disposable bookmark and verify the corresponding SQLite row; an anonymous request must be denied and leave the row count unchanged.
- Run the default and explicitly labelled readable-cookie response profiles, preserving native session/authentication source. Those remain the same family. JavaScript-necessity checks cover the declared profile operation only.
- Retain unknowns for incomplete controls, HTTP errors, ambiguous matching or failed restoration. Preserve original cookies/raw report; close contexts/processes and remove disposable data on completion/cancellation.

Results contain bounded booleans/counts/digests. Metadata-only scans, signed evidence, public verification keys and separate native-oracle measurements are retained privately under ignored `.local/ml-native-observations/tabinator/<run>/`. Their matching identifiers never become model identity features. Cookie values, credentials, user records, page text, code and request bodies do not enter those artifacts or training. No class label is inferred from rule output. A prototype result cannot enter training until a source lock, independent oracle class records and all preparation checks are in place. Ephemeral signing private keys are removed with the disposable run. These test public keys are not installed as API trust keys.

The bounded operation is `/api/auth/me` plus `/api/links`, through native API routes. The upstream frontend requires remote CDN scripts and is outside this offline prototype. No CDN source is substituted and no frontend compatibility claim is made. HTTP loopback does not supply validated TLS/HSTS evidence. The source syntax inventory is conservatively limited to partial application scope because separately mounted routers and other operations have not been functionally covered.
