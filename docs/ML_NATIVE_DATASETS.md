## Native seed protocol, specified before the new collection

The pinned Tabinator application supplies independent SQLite session-to-user and protected-bookmark readback controls, plus an anonymous mutation check. Before scanning, the browser's single native session cookie supplies separately sampled Secure/HttpOnly attributes. The scoped original/HttpOnly/restored functional controls establish whether JavaScript access is unnecessary for the declared profile operation. The native auth/database implementations are unchanged; the readable-cookie response profile is explicitly identified in the configuration hash.

- CK-001 may receive a change-warranted seed label only when the independent native controls pass and the observed authentication cookie lacks Secure.
- CK-002 additionally requires absent HttpOnly and successful authentication/functionality through complete original/restricted/restored controls without JavaScript access to the restricted cookie.
- All other observed categories receive needs-review labels until their independent context is established. No finding is invented when the scanner has no observation for a category.
- Missing, ambiguous or contradictory evidence remains uncertain. No contextual class is manufactured from a failed request, an unknown purpose, cookie names or the model's predictions.

The two response profiles remain **one family**. Their adapter implementation hash is now stable across profiles; configuration hashes retain the intervention. Historical snapshots remain unchanged. Existing reports and runtime models are unaffected.

The readable-cookie profile changes CK-001's full numeric input but does not create a second independent Secure-cookie cause. The audit therefore reports numeric variants separately from native scenario groups. Neither count substitutes for registered corpus eligibility.

Fresh collection emits a separate numeric seed receipt, authenticated with a domain-separated HMAC using the existing private family key. It includes only numeric model inputs, labels, opaque family identities, reason codes and provenance hashes. Native scan snapshots remain private and separate. Cookie values, accounts, bodies, page text, source code and URL identities do not enter the numeric dataset. The receipt proves local origin/integrity, not independent attestation or scientific truth. It is never accepted as an API project certificate.

## Run and inspect actual deficits

```powershell
npm run ml:projects:seeds -- --collect --output .local/project-native-seeds-001
```

Requires the existing pinned Tabinator and Jingo installations and private family key. It runs Tabinator default/readable-cookie/own-origin-framing and Jingo missing/early/late script-policy profiles, verifies receipts and completed cleanup/reload checks, deduplicates equivalent family/input/label records, preserves conflicts as uncertain, then writes seven category JSON files, provenance proofs, an audit and `training-status.json` to a new private directory. Existing output directories are refused. Omit `--collect` to assemble previously completed seed runs.

Exit code **2** means seed collection may have succeeded but training is blocked. These files deliberately use a seed schema and `eligibleForTraining: false`; they cannot impersonate registered development preparation. No held-out data is read and no model is fitted or promoted. Unknown/conflicting data cannot inflate eligible class counts.

`npm run ml:projects:candidate -- preflight --prepared .local/project-native-seeds-003` now recognises this acquisition format and reports the seven category deficits with exit 2. Candidate registration/fitting explicitly rejects it before importing the optimizer. It does not relax the original training gates or alter historical registered candidates; the trainer code change requires a new registration for future candidates.

## What must precede fitting

Source suitability and native functional coverage still need to establish twelve independent families, assigned eight training/four validation before fitting. Each category needs 30 materially distinct examples/class for training and 15/class for validation, each across three families. Registered preparation must run historical overlap and split audits. The seed corpus has neither a contextual cohort nor a frozen train/validation split.

Current producer deficits include validated TLS/HSTS applicability, complete supported native embedding/script compatibility, verified non-sensitive cookie preferences, necessary cross-site flows with scoped CSRF controls, and verified TLS resource upgrades. Broadening labels without those controls would train unsupported conclusions. These are data-collection/adapter requirements, not a missing PyTorch command.
