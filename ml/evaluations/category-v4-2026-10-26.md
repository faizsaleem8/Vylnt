## Data collected

All 140 real Chromium scenarios passed across the ten existing pinned applications. Each checks configuration, the original application's interaction and independent browser behavior before accepting an annotation. Five additional script attribute combinations exercise enforced CSP permit/exclude cases. Four cookie configurations verify JavaScript readability, expiry and whether the fixture cookie grants server access.

The extension command reproduces the original 190 rows exactly with the original private family key, then preserves them in the combined dataset. There are now 300 distinct family/context/label rows, 253 numeric variants and 11 actual families. Deduplication removes 33 of 333 source annotations. These are additional contexts, not additional independent applications. Train/validation/test contain 192/54/54 rows across 7/2/2 families; the same family/shared-input split algorithm remains in use.

Twenty checked cookie-purpose pairs have identical numeric inputs despite opposite independently verified purpose labels. Both labels remain; intent is not inferred from names or lifetime. There are 29 conflicting variants overall, including 25 in development. Unsupported/conflicting evidence must abstain.

## Candidate fitted

The eight-unit LSTM uses evidence-v3 inputs, at most 74 steps, seed 42 and 60 epochs. Training is balanced by category/class. Eligible JS-002 data contains 48 change-required and 48 contextual training examples, plus 16 of each for validation. No other category has both eligible classes in both development partitions, so all seven are explicitly unsupported.

Validation alone selects epoch 60, balanced loss 0.0245421, temperature 0.25 and thresholds 0.4/0.95. The global fallback is disabled. Logistic regression receives the same examples, tensors, partitions and sample weights; its validation-selected thresholds disable classification.

The 55,101-byte model passed four shortest/longest development-context numerical parity cases, maximum error `4.5294e-8` against `1e-6`. Eighty-four Python/JavaScript decision cases cover every category, both classifiers and supported threshold boundaries. Saturated logits cannot activate unsupported categories. The frozen candidate binds its model, logistic parameters, training record, registration, category policy and both parity fixtures.

## Qualification outcome

The evaluation command returned **blocked-before-test**. No test predictions or test-consumption marker were produced. There are only two held-out families, both previously seen, and 30 held-out numeric variants were also in the prior corpus. JS-002 has only 16 examples per class across two test families, below the 30-per-class/three-family requirement. Other categories lack class coverage as well.

The next qualification experiment needs genuinely new independent application families, a preregistered untouched holdout with at least ten families overall, and enough distinct eligible examples for each category being qualified. It must pass the original precision/recall/coverage/safety/comparator gates. Opposite purposes with indistinguishable inputs cannot be fixed by collecting more copies; keep those cases under review. Controlled results apply only to their tested scope.

The active v2 display-only model, raw findings, saved report versions, severity and GitHub blocking remain unchanged. The v4 candidate is developer-only and existing release commands reject its policy. No user training data, independent reviewers, deployment or Docker are required by this experiment.
